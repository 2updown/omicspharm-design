# 배지 색 규칙 · 서비스 상태값 정리

최종 수정 2026-10-28

OmicsPharm 서비스에서 화면에 배지로 보여 주는 모든 상태(프로젝트 단계, 견적, 결과보고서, 상담·문의, 인증·서류, 프로젝트 찾기)와 배지 색 규칙을 정리한 문서입니다. 웹과 Figma 화면의 모든 배지는 공통 컴포넌트 `badge_basic`만 사용합니다.

## 1. 배지 종류

| 종류 | 모양 | 쓰는 곳 | 예 |
|---|---|---|---|
| outline | 테두리와 글자만 있고 배경은 없음 | 큰 카테고리 | 단백체 분석, 대사체 분석, 매칭 추천 |
| tertiary | 연한 배경 + 진한 글자, 테두리 없음 | 단계·상태 | 의뢰접수, 견적 협의, 답변대기 |
| fill | 진한 배경 + 흰 글자 | 선정·확정·인증 같은 긍정 결과 | 선정, 최종 확인, 인증 완료 |

- 크기와 모양은 모든 배지가 같습니다: 높이 22px, 좌우 여백 8px, 모서리 8px, 글자 12px Medium.
- fill은 꼭 눈에 띄어야 하는 결과에만 씁니다. 목록의 한 줄에 fill 배지가 여러 개 붙지 않게 합니다.
- **목록·카드의 배지는 '분석 서비스(outline) + 프로젝트 단계(tertiary)' 두 개만 씁니다.** 단계 이름은 대시보드 프로젝트 진행 현황의 칸 이름과 같습니다.
- 견적서 상태(임시저장, 제출 완료 등)나 할 일은 배지로 붙이지 않고 카드 오른쪽에 보여 줍니다.
  - 내가 할 일 → 작은 outline 버튼 (예: 견적 작성, 이어서 작성, 견적 확인, 결과 등록, 의뢰 승인)
  - 기다리는 중 → 회색 글자 (예: OmicsPharm 검토 중, 클라이언트 확인 중)
- 모집중·비공개 같은 속성도 배지 대신 정보 줄의 글자로 보여 줍니다.

## 2. 색 규칙

| 색 | 의미 | 배경 / 글자 |
|---|---|---|
| 파랑 | 진행 중 | Blue/100 #D7EBFF / #0065F4 |
| 주황 | 확인·처리가 필요한 대기 | Orange/100 #FFECD2 / #FD4900 |
| 회색 | 완료·종료·임시 | Gray/100 #F5F5F5 / #525252 |
| 빨강 | 거절·삭제·반려 | Red/100 #FFE1E1 / #F00011 |
| 청록 (fill) | 선정·확정·인증 완료 | #009788 / #FFFFFF |
| 청록 (outline) | 카테고리 | 테두리·글자 #009788 |

- tertiary 배경은 100단계 색을 씁니다. 청록 tertiary만 100단계(#BFFDF1)가 너무 진해서 50단계(#EDFEFA)를 씁니다.
- 같은 상태라도 **화면을 보는 사람이 처리해야 하면 주황**, 다른 사람의 처리를 기다리는 중이면 파랑 또는 회색으로 표시합니다.
- 예외
  - 컨설턴트 화면의 '수정 요청'은 분석파트너의 응답을 기다리는 상태지만, 늦어지면 컨설턴트가 챙겨야 하므로 주황으로 표시합니다.
  - 상담·문의의 '답변대기'도 같은 이유로 누가 보든 주황으로 표시합니다.

## 3. 서비스 상태값

### 3-1. 프로젝트 단계

| 단계 | 클라이언트 | 컨설턴트 | 분석파트너 |
|---|---|---|---|
| 의뢰접수 | 파랑 | 주황 (승인 필요) | — |
| 의뢰승인 (컨설턴트: 의뢰확인) | 파랑 | 파랑 | — |
| 견적 확인 (컨설턴트: 견적 협의) | 주황 (견적 확인 필요) | 파랑 | — |
| 견적 요청 | — | — | 주황 (견적 작성 필요) |
| 견적 제출 | — | — | 파랑 |
| 미선정·거절 | — | — | 회색 |
| 계약 진행 중 | 파랑 | 파랑 | 파랑 |
| 분석 진행 중 | 파랑 | 파랑 | 파랑 |
| 보고서 등록 | — | 파랑 | (보고서 검토로 합침) |
| 보고서 검토 | 주황 (최종 승인 필요) | 파랑 | 파랑 |
| 프로젝트 완료 | 회색 | 회색 | 회색 |
| 삭제 | — | 빨강 | — |
| 임시저장 (제출 전) | 회색 | — | — |

- 세 역할 모두 '프로젝트 관리' 메뉴 하나에서 견적부터 완료까지 봅니다. 분석파트너는 선정되지 않은 견적도 '미선정·거절'로 남습니다.
- 분석파트너의 보고서 단계 (2026-10-28): 보고서 등록(OmicsPharm 검토)과 보고서 검토(클라이언트 확인)를 '보고서 검토' 한 단계로 합쳤습니다. 결과를 올린 뒤에는 파트너가 기다리기만 하므로, 단계 대신 카드 오른쪽 글자와 안내 박스로 구분합니다: OmicsPharm 검토 중 / 클라이언트 확인 중 / [결과 재등록] (컨설턴트가 재등록을 요청한 경우). 컨설턴트는 AI 초안 검토가 따로 있어 두 단계 그대로입니다.
- 단계 이름은 요구사항정의서의 상태값 시트를 따릅니다. 역할마다 보이는 이름과 단계는 아래처럼 다릅니다.

| 시트 상태값 | 클라이언트 화면 | 컨설턴트 화면 | 분석파트너 화면 |
|---|---|---|---|
| 임시저장 | 임시저장 | (보이지 않음) | (보이지 않음) |
| 의뢰접수 | 의뢰접수 | 의뢰접수 | (보이지 않음) |
| 의뢰확인 | 의뢰승인 | 의뢰확인 | (보이지 않음) |
| 견적 협의 | 견적 확인 | 견적 협의 | 견적 요청 · 견적 제출 |
| 계약 진행 중 | 계약 진행 중 | 계약 진행 중 | 계약 진행 중 |
| 분석 진행 중 | 분석 진행 중 | 분석 진행 중 | 분석 진행 중 |
| 보고서 등록 | 분석 진행 중으로 표시 | 보고서 등록 | 보고서 검토 |
| 보고서 검토 | 보고서 검토 | 보고서 검토 | 보고서 검토 |
| 보고서 승인 | (따로 보이지 않음 · 승인 즉시 프로젝트 완료) | 〃 | 〃 |
| 프로젝트 완료 | 프로젝트 완료 | 프로젝트 완료 | 프로젝트 완료 |

- 보고서 승인 → 프로젝트 완료: 클라이언트가 결과보고서의 [최종 승인]을 누르고 확인 창에서 승인하면, 그 즉시 프로젝트 완료로 표시합니다. 시트의 '보고서 승인'은 이 순간을 뜻하며 화면에 별도 단계로 보이지 않습니다. 승인 후에는 결과보고서를 수정할 수 없습니다.
- 만족도 평가: 완료 후 클라이언트에게 평가 칸이 보이며 [제출] 또는 [건너뛰기]를 누를 수 있습니다. 평가는 선택이고 완료 여부와 상관없습니다.
- 삭제: 계약 전(의뢰접수 ~ 견적 확인) 프로젝트만 삭제할 수 있고, 컨설턴트 화면에만 '삭제'로 남습니다.
- 삭제된 프로젝트의 견적 (2026-10-28): 견적은 지우지 않고 기록으로 남깁니다. 분석파트너 목록에서는 원래 있던 탭(견적 요청·견적 제출)에 그대로 두고 오른쪽에 '프로젝트 삭제'를 표시합니다. 카드를 누르면 '삭제된 프로젝트입니다. 목록에서 제거할까요?' 모달이 뜨고 [견적서 보기] / [목록에서 제거]를 고릅니다. 견적서는 보기만 되고, 임시저장 중이던 견적은 제출할 수 없습니다.

### 3-2. 견적 상태

- 파트너 견적의 공급가·분석 범위·일정이 바뀌어야 하면 컨설턴트가 [수정 요청]을 보내고, 분석파트너가 고쳐서 다시 제출합니다. 다시 제출하는 것이 분석파트너의 확인입니다. (2026-10-28: 컨설턴트가 직접 고친 뒤 확인을 요청하는 '변경 확인 요청'은 없앰)

**분석파트너 화면 (프로젝트 관리 > 견적 단계)**

견적서 상태는 목록 카드에서는 배지가 아니라 오른쪽 할 일로 보이고(작성 대기 → [견적 작성], 임시저장 → [이어서 작성], 수정 요청 → [견적 수정], 제출 완료 → 'OmicsPharm 검토 중', 프로젝트 삭제 → '프로젝트 삭제'), 견적서 상세 화면에서는 아래 색으로 표시합니다.

| 상태 | 색 |
|---|---|
| 작성 대기 · 임시저장 · 수정 요청 | 주황 |
| 제출 완료 · 클라이언트 검토 중 | 파랑 |
| 선정 | 청록 fill |
| 미선정 · 거절 | 회색 |

**컨설턴트 화면 (의뢰 상세 > 견적서 확인)**

| 상태 | 색 |
|---|---|
| 작성 대기 · 임시저장 · 전달 안 함 · 미선정 | 회색 |
| 제출 완료 · 클라이언트 검토 중 | 파랑 |
| 수정 요청 | 주황 |
| 거절 | 빨강 |
| 선정 | 청록 fill |

- 클라이언트 견적서를 보낸 뒤 기준 파트너에게 수정 요청을 해도 배지는 '선정' 그대로 둡니다. 수정 요청 중이라는 것은 위 안내 박스로 알립니다.

**클라이언트 화면 (견적 차수)**

| 상태 | 색 |
|---|---|
| 확인 대기 (최신 차수) | 주황 |
| 최종 확인 | 청록 fill |

### 3-3. 결과보고서 (분석파트너 화면)

| 상태 | 색 |
|---|---|
| OmicsPharm 검토 중 | 파랑 |
| 클라이언트 전달 완료 | 회색 |

- 2차 이후 결과 (2026-10-28): 클라이언트 [최종 승인] 전까지 횟수 제한이 없습니다. 클라이언트의 수정 요청은 [문의하기]로 컨설턴트에게 들어옵니다.
  - 컨설턴트 [직접 수정해서 보내기]: '컨설턴트 직접 수정' 항목 (배지 '전달 전' 주황, 전달 전에는 [직접 수정 취소] 가능). 분석파트너에게는 보이지 않습니다.
  - 컨설턴트 [결과 재등록 요청]: 요청 내용 필수. 분석파트너에게 '결과재등록요청' 알림, 결과 등록 칸이 'n차 결과 등록'으로 다시 열리고 카드 오른쪽은 [결과 재등록]. 올린 결과에는 요청 내용이 함께 남습니다.

### 3-5. 인증 · 서류

**분석파트너 인증 (컨설턴트 > 분석파트너 관리)**

| 상태 | 색 |
|---|---|
| 미제출 · 검토 대기 | 회색 |
| 인증 검토 | 파랑 |
| 재제출 요청 | 빨강 |
| 인증 완료 | 청록 fill |

**사업자등록증 (컨설턴트 > 의뢰 상세)**

| 상태 | 색 |
|---|---|
| 확인 전 · 재제출 | 주황 |
| 확인 완료 | 청록 fill |
| 미제출 · 재제출 요청 | 빨강 |

- 헤더 프로필과 내 정보 관리에 보이는 '인증 / 미인증' 표시는 인증 아이콘이 붙은 별도 배지로, 이 규칙의 대상이 아닙니다.

### 3-6. 프로젝트 찾기 카드

| 상태 | 종류·색 |
|---|---|
| 모집중 | fill 주황 |
| 마감 | fill 회색 |
| 비공개 | tertiary 회색 |

## 4. 새 상태가 생기면

1. 위 색 규칙에서 의미에 맞는 색을 고릅니다 (진행 = 파랑, 처리 필요 = 주황, 완료 = 회색, 거절 = 빨강, 긍정 결과 = 청록 fill).
2. 화면을 보는 사람(클라이언트·컨설턴트·분석파트너)마다 처리해야 하는지 따로 확인합니다.
3. 이 문서의 '3. 서비스 상태값'에서 해당 표에 추가합니다.
